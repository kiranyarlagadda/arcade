Draughts

Discs in the two player colours, crowned to promote

Same board, same squares. Pieces are the two accents so a player's colour is consistent from the draughts board to the paddle court. A king carries the queen's crown from the chess set at 85% ink, so promotion reads at a glance without a second disc stacked on top.

  • Start position with one king per side for reference; kings do not exist at the start of a real game.
  • Two inner rings at low opacity give the disc a turned edge without a gradient, so it stays crisp at 40px on a phone.
  • Mandatory captures are highlighted by the same teal dots as chess, on the landing square.

Aim Trainer

Classic on the 3 by 3, Freeshot anywhere

A target is four concentric marks in amber: ring, tinted disc, ring, dot. On a hit it collapses to a teal dot and eight radial ticks that fade in 180 ms; a miss leaves a rose cross for 120 ms where the pointer landed. Classic keeps three targets live in nine cells; Freeshot keeps six live anywhere, each at least a diameter from the next.

Aim Trainer · options

Raw input is what makes a sensitivity slider honest

In cursor mode the page cannot change pointer speed; the OS owns it. Raw mode takes pointer lock, hides the cursor, multiplies movementX by the slider and draws its own crosshair, which is how desktop trainers work and what lets a number transfer to a game. The panel is shown in raw mode. Every value persists and mirrors to an attribute, so a preset is a URL.

  • Pointer lock is requested with unadjustedMovement: true where supported, which bypasses OS acceleration. Losing the lock pauses the run, it does not end it.
  • Touch devices are cursor mode only; the slider is greyed out there and in cursor mode on desktop.
  • Modes are a registry, one file each, so the next mode is one file.

Cascade · working name

A tile with a bevel, in the palette's five hues

One rounded tile with two translucent highlight panels does the bevel without gradients. Colour is per piece, not per cell, so a line clear can flash by hue. The piece set below is a sample of a mixed 3-and-5 set, which is the current lead for Phase 4; the well is 8 wide, deliberately not the well everyone else uses.

  • Highlight panels are white at 14% and 10%, so the same tile file works for every hue and the bevel never needs a second asset.
  • Empty cells are a 2.5% white so the well has a visible grid without lines.
  • Files: design/cascade/tile-<hue>.svg, five in total.

Volley · working name

Two paddles in the player colours, a ball that leaves light

The court is the arena surface with a dashed centre line. Paddles glow in their player colour; the ball is ink with a four-dot trail that shortens as it slows. Nothing here is an asset file, it is all CSS and canvas, which is the point: the paddle game should cost under 10 KB.

3 : 2
  • Player one is always amber and always on the left; the AI opponent is always blue. Same mapping as draughts.
  • Serve direction is shown by a brief amber or blue pulse on the centre line, not by text.

Volley · online

A stateless introduction, then peer to peer

Two browsers cannot find each other unaided. A tiny service on the VPS holds a room code for a few minutes and passes the WebRTC handshake between them; after that the game runs on a direct data channel and the service is idle. It relays the game only when NAT traversal fails, about one pair in ten. Draughts goes online first, where a slow link is just a slow move; Volley reuses the plumbing and adds the real-time layer.

volley · online · rtt 34 msfeels local
volley · online · rtt 118 msplayable
volley · online · rtt 212 msfloaty, and the page says so
  • Room links look like /arcade/volley/#r=7f3k-q2mz. No accounts, no lobby, no chat, nothing to moderate.
  • Both sides run one deterministic 60 Hz simulation. The host sends full state at 30 Hz; the guest sends only input. Each moves its own paddle instantly, and on disagreement the host wins, corrected over a few frames rather than snapped.
  • About a kilobyte a second per player, relayed or not.
